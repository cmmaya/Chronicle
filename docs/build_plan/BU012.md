# BU012 — Implement Temporal Merge Layer for Transcripts

Status:
Pending

Goal:
Create a unified, chronological transcript by merging the independent, timestamped transcriptions from the microphone and system audio sources.

Context:
This is the final step in the backend refactor. It takes the separate, source-attributed transcription entries and assembles them into a single, coherent conversation log, ordered by time, as specified in the requirements.

Allowed Files:
- `src/transcriber/merger.py` (new file)
- `src/session/manager.py`

Dependencies:
Required:
- BU011

Blocks:
- BU013 (The original UI Integration BU)

Tasks:
- Create a `TranscriptMerger` class.
- This class will fetch all transcribed segments for a given session from storage.
- It will sort the segments based on their `timestamp_start` metadata.
- It will format the sorted segments into the final text format. The output must match this structure:

  ```text
  [00:12] MIC:
  I think we should deploy tomorrow

  [00:14] SYSTEM:
  Can we postpone to Friday?
  ```
- The final merged transcript should be saved to a file, e.g., `sessions/<session_id>/transcript.txt`.
- Integrate the `TranscriptMerger` into the `SessionManager` to be run after transcription is complete.

Out of Scope:
- Real-time display of the merged transcript.

Definition of Done:
[ ] A `TranscriptMerger` class is implemented.
[ ] The merger correctly fetches, sorts, and formats transcribed chunks from both sources.
[ ] A final `transcript.txt` file is generated in the session directory with content in the specified chronological format.
[ ] The process is triggered correctly by the `SessionManager`.

Reviewer Focus:
- The temporal sorting logic is correct.
- The final output format matches the requirement exactly.
- The integration with the session lifecycle is correct.
